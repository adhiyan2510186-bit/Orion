# Frontend visual work

A visual change is not done when it compiles. It is done when you have looked at a
screenshot of it and the gates pass. `tsc`, `next build` and a lit-pixel count cannot
tell you that a panel is ugly, that a number is set two points too small, or that an
overlay is swallowing clicks.

## Required reading, before the first edit

Read these in order. Do not skip them because a change looks small — every rule below
comes from one of them, and the arguments matter more than the values.

| File | What it settles |
|---|---|
| `DESIGN.md` | **Authoritative.** The aesthetic argument: why the neutrals are warm, why chrome is never blue, what glass is for, what motion is allowed. Every value has a stated reason; if you are about to contradict one, you need an ADR, not a preference. |
| `frontend/design/tokens.ts` | The values themselves, and the only source of them. Mirrors `DESIGN.md` by hand. |
| `UI_POLISH_PLAN.md` | The phase list, the decisions already made with the user (§4.1), and §3 — every place the existing code will fight a change. Read §3 before editing; it is a list of traps that have already been paid for once. |
| `PROGRESS.md` | Which phase is current and what is actually verified. |

Read `docs/extension-guide.md` too if the change adds a layer, colormap or theme.

## The organising idea

**Austere instrument, cinematic canvas.** The chrome is a flat, warm, matte instrument
housing. The WebGL viewport is a hole cut in it, and the water inside is atmospheric —
glow, grain, vignette, additive blending, camera motion. The boundary between the two
is the whole visual argument.

Practically, this decides most questions on its own:

- Glow, grain, vignette and additive blending belong **inside the canvas only**.
  Applying any of them to a panel is the single most damaging mistake available here.
- Glass is a **boundary** material, permitted only on surfaces that sit **over the
  canvas**, because what shows through them is the ocean. Never on the inspector, a
  `Panel`, a readout grid or the header.
- **No blue, teal or green in the chrome, ever.** Those hues are reserved for data
  encoding. A blue pixel always means a measurement; a blue button would make the user
  learn which blues mean something.

## Hard rules

These are from `CLAUDE.md` and are not style preferences. Nothing in this repo
mechanically enforces most of them — there is no ESLint config in `frontend/` — so they
hold only if you hold them.

1. **Tokens only.** No hardcoded colour, spacing or type size in a component. Colours
   come from `var(--color-*)`, type from a `text-*` utility, spacing from the 4px grid.
   `text-[13px]`, `#DA55A1` and `p-[7px]` in a component are all bugs. If a value you
   need does not exist, add it to `frontend/design/tokens.ts`, run `npm run theme`, and
   use the generated utility — do not inline it "just here".
2. **No `fetch` in a React component.** All network access goes through
   `frontend/lib/api/client.ts`. The layering is `components → hooks → lib/api →
   transport`, one-directional.
3. **Features import each other only through `index.ts`.** A file in `features/map/`
   may use `features/anomalies` only via `@/features/anomalies`, never by reaching into
   its `components/` or `hooks/`. If the barrel does not exist yet, add it.
4. **Never hand-edit generated files.** `frontend/types/argo.ts` and
   `backend/app/schemas/argo.py` are generated from `contracts/*.schema.json` — use
   `/sync-contracts`. `frontend/app/theme.generated.css` and `app/fonts.generated.css`
   are generated by `scripts/build-theme.mjs` and `scripts/fetch-fonts.mjs` — edit
   `design/tokens.ts` and regenerate.
5. **Animate `transform` and `opacity` only.** Never `width`, `height`, `top`, `left`,
   `box-shadow` or an SVG path length. Those animate on the main thread, and stuttering
   chrome undermines the product's central claim — 60k points at 60fps — in the most
   visible way available. Motion must explain a causal relationship; decoration does
   not ship (ADR 0005). Reduced motion must land on the **final** state, never a
   half-played one, and JS-driven motion must check `prefersReducedMotion()` itself
   because the CSS blanket rule cannot reach it.

## The loop

Both servers must be running: backend on :8000, frontend on :3000.

```
make dev-backend                 # or: backend/.venv/Scripts/python -m uvicorn app.main:app --port 8000 --app-dir backend
cd frontend && npm run dev
```

Then, for each change:

1. **Shoot first, for a baseline.** `npm run shoot -- before`
2. Make **one** coherent change.
3. `npm run shoot -- <label>` and **read the PNG**. Actually look at it. Name what is
   wrong with it before deciding it is fine — "it built" is not a review.
4. Iterate on 2–3 until the frame is right, not until the code is written.

`scripts/shoot.mjs` renders at **1920×1080**, the agreed capture target for the demo
recording. Do not review composition at another size: the 380px inspector's fold lands
somewhere different at every width. It also reports which fonts actually loaded — a
frame that silently fell back to Arial looks plausible and is wrong.

## Ending a run — both steps, every time

1. **Take a final screenshot and look at it.** `npm run shoot -- after`
2. **Run the gates.**

```
cd frontend && npm run typecheck && npm run build && npm run verify
```

`npm run verify` must report **18/18**. It counts its checks dynamically, so 18/18
means adding none and removing none — a new check is a deliberate conversation with the
user, not a side effect of a polish change.

Three of its checks are easy to break from a visual change, and `UI_POLISH_PLAN.md`
§3.5 lists every coupling in full:

- **Every overlay over the canvas must be `pointer-events: none`.** `verify` scans the
  WebGL framebuffer for a lit pixel and then clicks those coordinates through the DOM.
  An overlay that swallows the click kills picking, and selection with it.
- **No DOM overlay may tint the canvas.** The scan reads the framebuffer, the click
  goes through the DOM; a tinting overlay desynchronises them.
- **Keep these strings verbatim**: the `Natural language query` and `Time cursor`
  aria-labels, the `Play through time` aria-label, the `Basemap style` group role and
  its exact `Ocean` / `Satellite` / `Bare` button text, and the backend's
  `summary.answer` rendered as plain selectable text.
- **Zero console errors.** A React key warning, a deck.gl parameter warning or a 404 on
  a font all fail the run.

If a gate fails, report the actual output. Do not describe the work as done.

## Committing

Per `CLAUDE.md` you have standing authorization to push, but only when a phase gate
passes or a coherent piece of work is finished and boots. A sweep that touches every
component at once is the highest-regression-risk change available here — commit it
**separately** from the feature work around it so a visual regression stays bisectable.

Scope the commit `design`, `map`, `search`, `timeline` or `inspector`.
